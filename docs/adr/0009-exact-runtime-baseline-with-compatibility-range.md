# 精确运行时基线与独立兼容范围

Status: accepted

来源：FlowSVG [`86bb7ad`](https://github.com/yokingma/FlowSVG/blob/86bb7ad29484d7deb63142c1df84c6944a7c0eb4/docs/adr/0009-exact-runtime-baseline-with-compatibility-range.md)。本仓保留与 Skill 有关的决策和职责边界。

图解创作 skill 使用一个精确锁定且经过验收的 registry SDK 作为运行时基线，同时维护一个独立的兼容范围。本轮升级前基线为 `flowsvg@0.2.3` 及其完整性标识，当时兼容范围为 `>=0.2.2 <0.3.0`。

skill 安装和用户运行不动态解析兼容范围，也不跟随 npm `latest`。维护者在新的 patch 版本出现或明确提出升级时，先以候选版本执行独立安装、报告与诊断、静态导出以及可用浏览器检查；通过后才更新精确基线。若旧的最低版本仍通过兼容验收，支持范围下限保持不变。

这样可以同时表达可验证的兼容边界和可复现的实际运行环境。代价是 SDK 升级需要更新 manifest、lockfile 和验收记录；历史报告继续绑定原来的 SDK 版本与完整性，不自动重绑定。


## 2026-11-09：0.3.1 基线与支持策略

经用户确认，本轮基线升级为精确 registry `flowsvg@0.3.1`，支持声明收窄为 `0.3.1`。新增四种预设形状通过该版本的公开 `measureNodeLabel` 测量；不提供旧 SDK 回退分支。其他版本需独立兼容验收后再扩展声明。运行安装仍不解析支持范围，历史报告和查看证据仍绑定原 SDK 版本与完整性。平台和宿主支持只按当前候选实际执行的验收说明。

## 2026-11-13：0.4.0 基线

经用户授权，精确 registry 基线与支持声明升级为 `flowsvg@0.4.0`。文档强调配色与每次 flow 的连线自动着色策略由 SDK 统一实现，Skill 通过现有 JSON、校验及交付路径消费。保持现有制作流程与设计指导职责；历史报告和查看证据仍绑定各自的原 SDK 身份，不提供旧版兼容分支。
