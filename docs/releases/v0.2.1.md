## 中文

Flow Diagram Skill 0.2.1 改进安装包发布和示例资源组织，保留 `flowsvg@0.4.2` SDK 基线。

- GitHub 正式版本现在通过标签工作流发布：验收通过后提供通用 Skill ZIP 和 `SHA256SUMS`，并校验解包后的安装与运行。仓库新增发布 Skill，支持准备候选和按明确授权发布。
- 安装示例统一放在 `examples/`，使用 `complete-*` 和 `capabilities-*` 前缀。十一份图解 JSON 内容保持不变，引用、用户指南和预览工具同步更新；旧嵌套路径不再使用。
- WorkBuddy 打包可读取当前工作区，无需先提交。打包器校验目录深度、链接、文件类型、名称、版本和每种语言的案例数量，并记录输入与产物摘要。WorkBuddy 平台元数据只写入发布副本；平台发布保持独立。
- 明确继续任务、验证、诊断、导出和项目偏好管理的独立触发条件；更新中英文项目介绍、标志和带来源说明的静态示例。

安装：下载 `flow-diagram-skill-0.2.1.zip` 并校验 `SHA256SUMS`，将包内 `flow-diagram/` 放入宿主的 Skill 目录；也可按 README 使用 Skills CLI 安装。

运行要求：Node.js 20+、npm 和支持 Skills 及本地 Node 命令的助手。首次运行需要 npm registry 访问以准备隔离缓存；PNG、GIF 和浏览器检查另需预先安装 Chrome/Chromium，Skill 不下载浏览器。JSON、离线 HTML 和 SVG 可在无浏览器时生成。

已执行的本地程序检查：macOS arm64、Node 20.20.2、Chrome 158.0.8127.38 环境下，46 个回归文件的 334 项测试全部通过，无跳过；独立消费者验收 23 项通过，包含真实 Node 18.20.8 拒绝测试。Node 22.19.0 安装冒烟测试 2 项通过。410 个相对链接路径、222 个标题锚点及发布工作流静态检查通过。标签提交的 CI 结果保留在对应 GitHub Actions 运行中。

实际查看：白底 `complete-project-architecture` 的 HTML 首尾状态（0 / 36,000 ms）和首帧 SVG，未见明显文字裁切或布局异常。查看使用 1280 × 633 浏览器视口和完整页面截图。

限制与未执行项：未逐一查看中间动画帧、其他示例或 PNG/GIF；未执行 Windows 本地验收及助手宿主对话调用验收。程序检查与实际查看不代表全部平台或宿主验收。WorkBuddy 修正包仍需平台重新上传确认。

## English

Flow Diagram Skill 0.2.1 improves installation-package publishing and example organization while retaining the `flowsvg@0.4.2` SDK baseline.

- Formal GitHub versions now use a tag workflow. After acceptance passes, the workflow provides a generic Skill ZIP and `SHA256SUMS` and verifies the extracted installation and CLI. A repository-only release Skill supports candidate preparation and explicitly authorized publication.
- Installed examples now share `examples/` with `complete-*` and `capabilities-*` prefixes. All eleven diagram JSON files retain their bytes. References, user guides and the preview tool use the new paths; the old nested paths are no longer used.
- WorkBuddy packaging can read the current working tree without a commit. The packager validates directory depth, links, file kinds, name, version and per-language example counts, and records input and artifact digests. Platform metadata is written only to the release copy; WorkBuddy publication remains independent.
- Clarify independent triggers for resuming tasks, validation, diagnosis, exports and project preferences. Refresh both project introductions, the logo and attributed static examples.

Installation: download `flow-diagram-skill-0.2.1.zip`, verify `SHA256SUMS`, and place its `flow-diagram/` directory in your host's Skill directory. The README also provides Skills CLI installation commands.

Requirements: Node.js 20+, npm, and an assistant that supports Skills and local Node commands. The first run needs npm registry access to prepare an isolated cache. PNG, GIF and browser inspection also require separately installed Chrome/Chromium; the Skill never downloads a browser. JSON, offline HTML and SVG generation work without a browser.

Executed local programmatic checks: on macOS arm64 with Node 20.20.2 and Chrome 158.0.8127.38, all 334 tests in 46 regression files passed with no skips. All 23 independent consumer checks passed, including rejection by real Node 18.20.8. Both installation smoke tests on Node 22.19.0 passed. Checks for 410 relative link paths, 222 heading fragments and release-workflow syntax passed. CI results for the tag commit are retained in its GitHub Actions run.

Actual viewing: the white-background `complete-project-architecture` HTML at the initial and final states (0 / 36,000 ms), plus its initial SVG, showed no obvious text clipping or layout problems. Viewing used a 1280 × 633 browser viewport and full-page captures.

Limitations and unperformed checks: intermediate animation frames, other examples and PNG/GIF were not individually viewed. Local Windows acceptance and conversational invocation inside an assistant host were not performed. Programmatic checks and actual viewing do not establish acceptance on every platform or host. The corrected WorkBuddy package still needs a new platform upload for confirmation.
