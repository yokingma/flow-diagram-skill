# 源码注释

修改源码时同步核对相邻注释。新增模块、公开 API 或复杂状态/算法时，按下面的层次补充说明。

## 文件与公开契约

- 重要实现文件顶部说明模块职责、上下游关系及运行环境约束；简单转导出文件无需固定文件头。
- 公开函数、类、组件与关键类型使用 JSDoc，让说明随类型声明进入编辑器提示。
- 说明类型签名无法表达的信息：单位、坐标系、默认值、时间边界、状态变化、错误和资源生命周期。
- 对有特殊语义的方法或字段就近补充注释；`@param`、`@returns`、`@throws` 按信息需要使用。

## 内部实现

- 关键类说明状态模型与责任边界；复杂函数说明处理策略与必须保持的不变量。
- 在容易误改的分支旁解释原因，例如显隐与路由障碍的不同判定、事件重入时的销毁保护、异步请求令牌。
- 按理解成本选择注释位置；简单语句通过命名表达。复杂类型和多条语句展开排版，便于对应注释阅读。
- 源码注释统一使用英文；保留代码标识符和领域术语，避免重复的双语段落。

## 核对

- 注释依据实际实现和行为测试；发现实现与规格不一致时单独记录问题，避免用注释承诺尚未实现的行为。
- 局部规则在源码中给出足够说明；架构背景可链接 `docs/adr/`，避免复制完整设计文档。
- 注释与排版改动复用已有检查；核对声明文件保留关键 JSDoc，并确认类型、语法结构和执行逻辑一致。
