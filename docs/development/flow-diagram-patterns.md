# Flow Diagram implementation patterns

## Partial review validity

Keep source requirements separate from capture facts. Detect recursive reuse cycles with the current operation locator and entry ID, since distinct operations can share one original capture. Only verified captures retain active evidence IDs; invalid registrations carry their failure reason and exact-condition recapture action. Separate request planning from environment execution. Persist complete valid evidence requests before browser lookup; reject malformed settings before writing. Verify stored combined observations per entry, retain valid materials and all invalid-entry issues, and carry saved invalid facts in an explicit result object through every aggregation path. Invalid historical observations with issues retain an explicit unresolved-issues observation; image loss cannot resolve an issue.

## On-demand evidence

Keep design snapshots, capture operations and actual-viewing attestations separate. Plan the complete required surface set before starting a browser. Verify both actual source and screenshot identities; capture only missing conditions. Preserve terminal partial outcomes and logical surface coverage independently from the number of captures. Screenshot damage invalidates coverage, while source or identity corruption blocks adoption.

Ordinary skill tasks retain only the final diagram and portable report after success. Full task history is an explicit user choice.

Validate review-only CLI options at the command boundary. Unsupported commands must report an option-scope error instead of silently ignoring evidence input.

Keep file delivery eligibility separate from quality coverage. Once validation, compilation and every requested file succeed, optional browser or visual failures remain in the report while finalization can publish the complete files.

This project maintenance document covers the CLI in `skills/flow-diagram/scripts/`. It is outside the skill installation unit; see the [maintenance guide](flow-diagram-maintenance.md) for verification and installation boundaries.

## Read-only validation

`validation.mjs` reads a draft once or verifies an explicitly selected saved source. It returns the shared `document-checks.mjs` validation/compilation results and optional `--geometry` computations without allocating history or calling `saveReport`. Keep `revision: null`, an exact input hash and `validation.snapshotCreated: false`. `validation.sourceRevision` identifies only an explicitly verified saved input; newly computed diagnostics still use `sourceRevision: null`. Formal decisions require a saved authoring report. Runtime cache preparation remains independent of diagram persistence.

## Layout diagnostics and measurement estimates

The preset kinds (`diamond`, `parallelogram`, `document`, `predefinedProcess`) use public `measureNodeLabel` for height and auxiliary width estimates. `label-measurement.mjs` selects the API by node kind, counts lines from public frames at the measured height, and collects initial/animated preset labels for draft measurement. Empty preset labels retain contour clearance. Standalone preset inputs accept a string or nonempty label-version array; top-level batch labels retain their metadata meaning. Width estimates retain their label field location and allow backfill and layout to continue. Ordinary nodes keep their existing initial-label estimator. Layout remains static-only; use draft measurement after adding animation.

`measurement-sources.mjs` maps initial and replacement values to actual zero-based input paths without parsing node IDs. Preserve public SDK `path`, `versionIndex`, `dimension` and `message`; append `sourcePath` and dimension-specific `nextStep`. Independent and batch diagnostics keep their existing measured status, while draft estimates expose the actual path in `location` and accompany successful results and backfill. Per-version diagnostics retain the SDK index from that individual call and use `sourcePath` for the original version. Suggestions inspect dimensions and block type rather than English messages. Do not infer missing graph-block heights or treat an algorithmic overflow as actual glyph or aesthetic proof.

Keep diagnostic `nextStep` text aligned with [the authorization and decision rules](../../skills/flow-diagram/references/diagnostics-and-revisions.md). Already authorized mechanical corrections can proceed; changes to meaning or outside the current authorization require a user decision. Informational geometry and measurement observations do not create approval or exception requirements.

Use public SDK frame `contentLayout.lines` to count distinct baseline `y` positions for deterministic structural estimates. Share ordinary-label measurement in `label-measurement.mjs`: read public `labelLines` and calibrate line spacing with a two-line public frame at the same width and typography. SDK frames retain overflowing lines, so a minimal probe height is sufficient. The pinned baseline reserves 24 vertical units for ordinary labels. Keep this baseline constant next to the calibration and update both with a verified SDK upgrade. Label overflow reasons reuse this estimator at the sampled node width and label; diagnostic code never reads private compiled-diagram state. Do not infer rows from height/font or count marker/tag fragments separately. Keep the method label explicit and distinguish [baseline counts from optional text records](../../skills/flow-diagram/references/tool-contract.md#inspect-estimated-text-lines): counts retain graph-internal label positions supplied by the SDK, while `estimatedLines` excludes those labels. Neither output measures browser glyph pixels. Source-bound observation IDs identify calculation inputs and times, without a warning-approval workflow.

## Layout command

`layout.mjs` validates source fields and the independent plan, measures planned structured-content and label-only nodes at their final widths, and runs public SDK checks on the geometry result before publishing a new draft. Optional geometry observations bind the output hash with a null source revision. `atomic-draft.mjs` shares exclusive copy publication between layout and height backfill. `editable-draft.mjs` owns explicit `--in-place` edits of canonical task-root sources, using the same operation reservation as author/finalize, complete sibling staging, source-identity recheck and atomic rename. Check cancellation before publication. Generated current JSON, checkpoints, external files and aliases remain protected. Finalization compares any task-root source to the current author input before publishing.

## Layout-plan validation

Keep `layout-plan.mjs` pure and independent of SDK installation. Its validation interface returns field-level diagnostics and does not mutate the plan or draft. Run public SDK draft validation separately before layout. A group primitive changes the local coordinate scope only when its ID names an existing group; anonymous rows and columns preserve the enclosing semantic parent. Overrides accept geometry only. Reject group spacing overrides unless their target is expanded as a group container in the plan. Unassigned nodes keep their existing geometry. See the [versioned contract](../../skills/flow-diagram/references/layout-plan.md).

## Layout plan workflow

Use the single workflow in [static-layout](../../skills/flow-diagram/references/static-layout.md#layout-plan-workflow) for draft, measurement, layout, validation, author/review and finalization. Keep Agent semantic choices separate from deterministic geometry. The layout-assistance examples are teaching data: five layers establish reading order only, and four edges are teaching relations; they do not imply production facts or call timing.

## Layered teaching examples

The pure layout geometry boundary changes only viewport dimensions, node geometry and explicitly selected edge route/port fields. Plan order controls placement; document arrays retain their original order. Resolve measurement widths before calling the SDK. Use the greater of authored height, default height and measured height as the automatic height floor while preserving exact height overrides. Derive expanded-group widths from child bounds before label measurement; group width does not depend on measured heights. Validate group measurements against that derived width and include the group's own required height when arranging later layers. Expanded groups include unmanaged children's local bounds. Override-only nodes keep unspecified geometry and are not implicitly measured. Missing canvas dimensions grow from the input viewport; explicit dimensions stay fixed and later checks retain overflow warnings.

Keep layered architecture examples explicit about semantics. Use groups for named explanatory layers, leave room for headings, place at least two columns on a shared row, and label every cross-layer relation whose direction matters. A governance sidebar may use dashed annotation edges, but its labels must say when the relation is explanatory and not a runtime dependency. Document that layer order is a reading aid rather than call order and that grouping does not establish deployment or trust boundaries without source evidence. Measure structured content and initial labels from the draft with the document typography, apply supported height increases to the same source draft, and inspect every requested final artifact independently.

Its HTML plan discards the SDK-only overview before applying the actual capture bound, keeping unique timeline times and initial/final priority. Overview is an explicitly labeled camera-only inspection projection; timeline points preserve authored actions. Fixed bounds and omitted candidates describe partial coverage.

## Required delivery coverage

Default capture and formal review are separate. `formal-review.mjs` configures explicit intent, and `updateQualityCoverage` removes formal conclusions when review is not requested. Default actual-HTML capture reports `captured`; only explicit review requests use `awaiting-review` and registered viewing counts. `--preview` adds SDK capture independently, and `--samples` also bounds actual HTML capture. Formal coverage checks structural execution and requested viewing surfaces, never optional geometry approval.

Treat file completion and quality coverage as separate facts. The installed CLI records structural checks, the actual offline HTML states, and each requested SVG/PNG display surface in `qualityCoverage`. Native intrinsic dimensions and the resolved theme backdrop are the defaults when no display size is specified. Review-only revisions carry the parent delivery request and artifact identities so earlier static files cannot disappear from the required set. Viewer issues remain `unresolved-issues` with their supplied next action; missing browser or actual viewing remains `incomplete`. Formal completion reflects declared coverage, even when viewer issues remain unresolved.

Missing static evidence must identify the artifact ID, expected display dimensions and carrying backdrop, then give explicit artifact-preview settings and the capture/view/review steps. Ordinary sampled previews do not cover actual static files. Do not infer or inherit display settings from preview dimensions.

## Read-only review preparation

`review-contract.mjs` owns the complete strict shape for preview, HTML and formal-image review inputs. Source-specific readers retain identity checks. `review-preflight.mjs` validates all supplied inputs and source bytes before any author revision allocation or expensive execution; it exposes verified materials for independent review recording. Template requests persist separately under `records/formal-requests`, binding the source report hash. Evidence terminal records also preserve formal intent. ## Independent observations and report projection

`inheritRevision` preserves parent provenance and same-source delivery requests before runtime preparation, returning the parent report to the workflow. After public document validation establishes theme and actual SDK identity, `inheritDeliveryContext` adopts completed files, inherited exports and artifact evidence only when source/theme/SDK all match. A baseline change retains export requirements without treating old bytes as new completion. Historical managed HTML still rejects an SDK mismatch; reconstruct a fresh empty managed region while preserving authorized outer content.

Keep `v###` for explicitly retained checkpoint or formal-review sources and `review-<sha256>` for append-only observations. Independent review consumes source preflight and complete actual-file/screenshot identity without author, compiler, renderer or browser calls. Normalize accepted semantic inputs before computing the ID; publish a complete record exclusively, and revalidate the existing record/source on duplicate reuse.

`readSavedRevisions` is the shared unchanged-context ancestry reader. `loadReviewRecords` revalidates each applicable immutable record and its actual source/evidence. `aggregateReviews` returns an in-memory report clone; finalization keeps its original file collector and publishes the projection. Match HTML by actual delivered hash, target display and requested point ID/time. Preserve the selected required set; repeated source attestations count once and retain source hashes. Union every unresolved issue rather than choosing the last clean observation. Keep considered/adopted record IDs explicit. Corrupted applicable records fail closed and preserve recovery files.

## Independent formal-image observations

`artifact-review-source.mjs` resolves the explicit evidence source separately from the real diagram subject. `loadArtifactEvidenceSource` returns its hash-bound locator and actual source context; `verifyArtifactReviewEntries` verifies settings, original artifact identity and actual evidence bytes. Review preflight, templates and stored-record verification share this interface. Evidence source IDs never occupy `revision.id`.

`review-projection.mjs` unions every requested evidence surface from same-context ancestry and applicable sources before evaluating viewing. Different observations for one evidence ID retain all attestations and issues. `finalize.mjs` preserves full portable surface identity rather than reducing it to dimensions and hashes. `loadReviewRecords` also revalidates saved authoring artifact observations before their status can enter a projection.

## Agent-composed HTML

`author --html` reads one Agent page before allocation, validates the single Skill-owned playback region and preserves surrounding bytes. `html-page.mjs` fills an empty starter region or verifies the exact existing region against the current input bytes, SDK identity and theme. Playback uses the opaque complete result of public `renderHtml` in an iframe. Page provenance keeps portable source/output hashes. Inspect the outer saved HTML while locating playback controls inside the managed frame; root SDK-only HTML remains the ordinary no-page path.

## Animated editable page checks

Observe the complete offline page, including network or local-file requests from the outer document or iframe. A blocked request is still a failed offline dependency check, with retained delivery files and evidence. Record the visible caption and SVG text alongside requested sample time and actual range progress. Round fractional boundary seeks upward by less than one microsecond to avoid selecting a preceding beat after range serialization. Exercise backward reconstruction through visible controls and compare outer static text before/after; capture remains separate from actual viewing. Author-controlled minimum frame width belongs to starter page CSS, inside an accessible horizontal reading area, rather than SDK layout code.

## Current export continuation

`export-request.mjs` persists serializable export/capture settings and exact manifest/GIF-options bytes in the current report. Omitted settings survive current-source continuation and same-task draft edits; explicit options replace their values. Every current author run regenerates requested outputs into private staging, including unchanged requests. Saved completion never proves new completion. A batch retains exact source/SDK binding; changed bytes fail preflight rather than silently rebinding. Browser selection stays outside the saved request.

Current capture continuation preserves `workingDraft.editableSource` independently of the generated `input.path`. Explicit author input resets its consumed path/hash binding. Finalization verifies task-owned source bytes through that binding before publication and scoped cleanup.
