# Capability overview

[Diagram source](capability-overview.json)

**Question:** How can a reader compare responsibilities while distinguishing existing work, candidate capabilities and unknown conditions?

**Teaching facts:** This fictional public-information studio already organizes source material and edits content. Publishing support is a candidate capability. It uses public information; external authorization, model integration and launch timing remain unknown.

**Why this composition:** Three equal-height cards use the same title, responsibility and scope order. Their content states each capability's status, while the heading and closing limitation establish context. No edges are drawn because the arrangement compares responsibilities without asserting calls or execution order. Compact cards preserve the reading hierarchy without excessive empty space.

**Display and limits:** Static light-background diagram, 960 × 484 units, intended for a 720 × 363 PNG with actual HTML displayed at a 1440 × 1000 browser viewport. Use it for capability or responsibility inventories. Execution order, dependencies and state changes need a different composition. Adapted content needs fresh measurement and actual viewing.

For current viewing coverage and unperformed checks, read the [library viewing scope](README.md#display-conditions-and-limits).
