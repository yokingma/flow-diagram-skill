# Test Flow Diagram

把用户常见的手动测试步骤流程化。用户指定本次任务；主任务组织执行和转交澄清，子代理通过全局安装的 `flow-diagram` 正常制作，用户检查产物并作出最终判断。

手动调用示例：

```text
/test-flow-diagram 制作 RAG 工作流程的流程图动画，分阶段展示提问、检索、上下文组装和回答生成。
```

在 Codex 中可显式使用 `$test-flow-diagram`。本 Skill 随仓库源码维护，不属于生产 `skills/flow-diagram/` 安装单元。

## 1. 准备本次运行

保留用户原始需求和显式授权的输入。没有具体任务时，先询问用户要测什么；示例不作为默认测试题目。

在本仓根目录下独占创建 `.scratch/skill-generation-test/runs/<时间戳和唯一后缀>/`，解析为真实绝对路径，作为本次运行目录。创建 `request.md` 保存原始需求、授权输入的绝对路径；后续澄清追加保存，不改写原始需求。

定位当前宿主全局安装的 `flow-diagram`；本项目常用入口为 `~/.agents/skills/flow-diagram`。记录安装入口、解析后的真实路径及 `SKILL.md` 是否可读。多个入口无法确定实际使用者时询问用户。入口缺失、软链断开或文件不可读时，在 `run.md` 记录原因并停止，提示用户或开发者手动安装；不自动安装、重建软链或改用源码目录。

初始化 `run.md`，记录时间、原始需求链接、安装入口及真实路径、当前宿主和可获取的版本信息。版本从安装资源或本次产物报告获取；未知信息标为未知。正常复用生产 Skill 的运行时缓存，不强制重新安装依赖。

在 `run.md` 顶部维护唯一的“当前状态”和更新时间，阶段变化时更新；历史步骤记入带时间的执行记录。执行状态与用户验收状态分开，例如“执行结束；待用户检查”。准备和收尾由主任务维护，制作阶段由子代理维护。

主任务在启动子代理前保存 `installed-before.json`：记录采集时间、安装入口及真实路径，以及安装目录内每个常规文件的相对路径、字节数和 SHA-256，按相对路径排序。覆盖指导、参考、教学范例、脚本、元数据及 runtime manifest/lock 等安装资源；排除 `.git/`、`node_modules/`、缓存和生成产物，明确写出实际排除的路径。若安装内容中还有软链，记录其链接目标及目标文件摘要；目录软链或无法读取的资源导致清单不完整时，记录具体原因并停止。只保存身份清单，不另建被测安装副本。

完成条件：本次运行目录和记录已创建，任务明确，全局安装入口可读且起始内容清单完整；否则已有具体的阻塞记录。

## 2. 开启干净上下文子代理

使用宿主支持的新上下文子代理，不继承开发对话历史。例如 `spawn_agent` 提供 `fork_turns` 时设为 `"none"`。主任务不先代做图解，不把开发总结、实现方案或预期答案传给子代理。

只交接原始需求及后续用户澄清、授权输入位置、全局安装入口、本次运行目录、下列执行约束，以及第 3 节的记录字段和保留要求：

> 你负责本次 Flow Diagram 实际生成测试。以给定运行目录为工作目录，通过已全局安装的 `/flow-diagram <原始需求>` 完成任务。宿主没有独立的 Skill/slash 调用工具时，读取给定安装入口的 `SKILL.md` 并遵循其执行；发送命令文本本身不代表宿主已解析命令。
>
> 可读材料限于本次需求、用户显式授权的输入、安装入口内的正常指导/参考/脚本/教学范例，以及本次新生成的文件。辅助工具输出目录仅按第 3 节核对已有文件路径和元数据。安装入口可以软链指向源码仓库，正常读取该入口内资源是允许的。不要另行搜索开发源码、开发记录、历史交付或其他测试运行。仓库工作约束仍然有效。
>
> 把本次运行目录作为工作目录，按生产 Skill 正常创建制作工作区和最终产物。遵循其制作、校验、查看修改和交付流程；可修正本次图解，不修改安装内容或生产 Skill。向本次 `run.md` 及时追加带时间的关键决策和问题，维护顶部当前状态及更新时间。需要用户决定时把问题交回主任务，等待回答后继续。
>
> Agent 的视觉查看仅作辅助。返回最终产物和报告位置、已做检查、实际查看范围、遗留问题及未执行项，用户保留最终判断。失败或取消时保留本次可恢复工作；没有新证据时停止重复重试并报告下一步。

启动前将实际发送的完整任务正文保存为 `handoff.md`，包含展开后的执行约束和第 3 节要求，不能只写“已交接”。同文件记录显式设置的上下文选项，启动后补充返回的子代理标识，并在 `run.md` 链接。后续向子代理发送的澄清和补充指令按时间追加原文；不收集完整聊天或逐条工具日志。该记录说明实际交接了什么，不作为子代理已遵守全部约束的证明。

子代理能力不可用，或无法保证不继承开发历史时，记录限制并停止。不要在开发对话中直接出图后称为干净上下文测试。这里的隔离依靠新上下文和读取约束，不声称文件系统强制隔离。

完成条件：已启动符合上述范围的子代理，实际交接正文、上下文设置及子代理标识可查；或已记录无法启动的原因。

## 3. 转交澄清并记录执行

子代理提出影响含义、关系或范围的问题时，主任务向用户转交，把回答追加到 `request.md` 并传回同一个子代理。主任务不根据开发历史替用户补答案。已有明确默认值的事项按生产 Skill 执行。

执行过程中在同一 `run.md` 维护以下记录，正常命令和完整 stdout 不逐条抄写：

- **关键决策**：要解决的问题、采用的决定、决定者（用户或 Agent）、依据及影响的产物或检查范围。包含影响结果的假设、内容或表现取舍，以及由错误或查看触发的实质修正。
- **问题与处理**：现象、产物/阶段位置、处理、复查结果和遗留影响。重试追加处理结果，保留失败经过；图解已修正不代表生产 Skill 缺陷已修复。
- **检查与查看**：引用本次实际报告，记录执行结果；实际查看写明文件、展示尺寸及动画阶段。未查看的表面、播放过程或导出文件分别列为缺口。

发现实质视觉问题时，在覆盖当前产物前，将能说明问题的现有截图保存到运行目录的 `evidence/`；修正后保留对应复查截图，使用不同文件名。问题记录链接前后截图，注明所对应的产物内容身份、展示尺寸、背景及动画阶段。没有截图或问题只在连续播放中出现时，记录观察和证据缺口，不补造旧画面。没有问题的常规截图不要求全部保留。

浏览器等辅助工具的截图、日志和快照优先指定到运行目录的 `tool-output/`，不改变全局工具配置。工具只能写到仓库根目录等外部位置时，使用前记录该输出目录已有文件的路径和元数据，使用后登记本次实际生成的文件。这里只核对输出归属，不读取旧内容作制作参考。现有同名文件可能被覆盖时，改用新名称或其他输出方式。

`run.md` 位于运行目录根部，始终在生产 Skill 的临时制作工作区之外。子代理在收尾清理前，将临时 `issues.md` 中需要回溯的问题和处理摘要写入 `run.md`，核对关键问题截图已保留；引用保留的最终报告和文件，不让唯一问题记录随临时工作区删除。其他中间文件按生产 Skill 的正常清理规则处理。

主任务负责准备和收尾记录，子代理执行期间负责追加；转交澄清时让子代理等待，避免双方同时改写记录。用户补充意见与 Agent 观察注明来源，不相互替代。

完成条件：影响结果的决策、问题及处理可从记录追溯，关键视觉问题有截图链接或明确的证据缺口，工具额外输出已登记；或执行阻塞已有位置、原因和下一步。

## 4. 交付用户检查

主任务读取子代理返回的本次记录，核对报告中引用的产物路径实际存在。测试结束或中断都更新 `run.md`，并向用户提供产物、`request.md` 和 `run.md` 的可访问链接。

核对本次登记的辅助工具输出；仓库根目录等外部位置的文件，仅将能确认是本次新建且未被其他任务修改的文件归档到 `tool-output/`，核对副本后移除对应原文件。归属不明、已有或被其他任务改写的文件保持原样，记录位置与原因；不整目录清理。记录本次临时服务和浏览器会话的关闭结果，不能确认关闭时列为遗留事项。

子代理停止执行后，主任务通过同一个全局入口按起始规则重新采集 `installed-after.json`，比较入口真实路径、文件清单和内容摘要。在 `run.md` 链接两份清单并记录新增、删除、修改的资源或软链目标变化。发现变化时保留产物，将本次标为“被测内容发生变化”，不归属于单一 Skill 内容身份，建议在内容稳定后重新测试；结束清单无法完成时，记录“结束身份检查未完成”及原因。两次清单相同仅说明采集时一致，不保证期间未发生短暂修改。内容身份采集由主任务完成，不扩大子代理的读取范围。

分别报告：

- **交付完成**：实际生成的文件；缺失文件和恢复工作位置。
- **程序检查**：已执行的检查及结果；未运行的测试不能写成通过。
- **实际查看**：Agent 看过的文件、尺寸和动画阶段，以及辅助观察。
- **未执行与遗留问题**：缺少的能力、未查看范围、未解决问题及建议修正位置。

本次产物默认位于运行目录内的 `.diagrams/<图解名>/`。保留 `request.md`、`handoff.md`、`run.md`、安装内容身份清单、最终产物及报告，以及实际产生的关键截图和归档工具输出；失败时保留可恢复工作。每次使用新目录，不覆盖历史运行，也不自动修改生产 Skill 或全局安装。

收尾时更新顶部当前状态，注明执行已结束、受阻或取消，以及用户是否已验收。文件生成、机器检查成功或 Agent 辅助查看都不代替用户验收；仅在用户明确给出结论后记录其判断。
